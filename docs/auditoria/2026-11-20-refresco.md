# Auditoría · Refresco de datos tras guardar/editar/borrar · 2026-11-20

Origen: pedido del dueño «analiza si hay más cosas así que actualizas y no se ve al instante en todo»
(caso inicial: Categorías/Marcas/Unidades, commit 52198c8). Rol: desarrollador.

## Resumen

El patrón no era aislado. Un análisis estático de las 298 escrituras del front (insert/update/upsert/delete,
RPC que escriben y edge functions) contra las ~490 consultas de React Query encontró **178 escrituras** que
no invalidan al menos una consulta de la MISMA pantalla que muestra lo escrito, y prácticamente todas dejan
sin refrescar consultas de OTRAS pantallas (listas, saldos, dashboard, kardex) hasta recargar o vencer su
`staleTime` (3–15 min). Parchar 178 sitios a mano no escala (cada pantalla nueva vuelve a olvidarlo), así que
se resolvió con una **red de seguridad central** y se corrigieron las causas que la red no cubre.

## Red de seguridad central (nuevo)

| Pieza | Archivo | Qué hace |
|---|---|---|
| Observador de escrituras | `src/lib/refresco/refrescoTrasEscritura.ts` (`instalarRefrescoTrasEscritura`, instalado en `src/App.tsx` junto al QueryClient) | Observa las peticiones que salen por `fetch` (el cliente Supabase usa el fetch global; mismo mecanismo que el medidor `src/lib/dataUsage.ts`). Una escritura exitosa a `/rest/v1/<tabla>`, a una RPC que escribe o a una edge function que escribe (facturama al timbrar, admin-users, user-lifecycle) invalida SOLO las consultas que leen lo afectado. |
| Mapa generado | `src/lib/refresco/lectores.generated.ts` ← `scripts/gen-mapa-refresco.ts` | tabla → claves que la leen (del código: `.from`, selects embebidos, FKs `alias:columna(...)`, RPC de lectura resueltas con el SQL de las migraciones, funciones auxiliares a 2 niveles); tabla → tablas que cambian sus triggers; RPC → tablas que escribe (de `supabase/migrations`). Regenerar: `bunx tsx scripts/gen-mapa-refresco.ts`. |
| Helper manual | `invalidarTrasEscritura(qc, ['tabla' \| 'rpc:fn'])` | Mismo mapa, para usarlo a mano si hiciera falta. |
| Pruebas | `src/test/refrescoTrasEscritura.test.ts` | Detección de escrituras, expansión por triggers/RPC, claves, agrupamiento y que lecturas/errores no disparen nada. |

Cuidado del consumo (egress):
- Solo se re-descargan las consultas **visibles** (refetchType `active`); las de otras pantallas quedan marcadas y se recargan al abrirlas.
- Escrituras seguidas (encabezado + líneas + RPC) se agrupan: 400 ms tras la última, máx. 2 s → un solo refresco.
- Se omiten las consultas que ya se recargaron después de la escritura (la pantalla ya invalidó a mano) y no se cancela una descarga en curso (`cancelRefetch: false`; evita además bucles si un `queryFn` escribe).
- No propaga el total de stock `stock_almacen → productos` ni `ventas → clientes` (público general): el catálogo de productos ya lo refresca el canal Realtime global agrupado (`useProductosRealtime`); repetirlo bajaría el catálogo dos veces por venta. Editar un producto directamente sí refresca.
- Telemetría ignorada: `vendedor_ubicaciones*`, `consumo_datos`, `publicidad_vistas`, `notification_views`, `broadcast_reads`.

## Qué NO cubre (y por qué)

- **Cambios hechos en OTRO dispositivo/usuario**: eso es tarea del Realtime existente (`useRealtimeInvalidate`, `useProductosRealtime`); no se amplió para no subir el consumo.
- Edge functions no listadas en `ESCRITURAS_EDGE` (WhatsApp, Stripe/Openpay, correo, IA): no escriben datos que muestren estas pantallas o lo hacen de forma asíncrona (webhooks).
- Consultas que leen por edge function (`tienda-*`, `admin-stats-*`, `rep-pendientes`, `csd_status`): el mapa no las detecta; dependen de sus invalidaciones explícitas.
- `EntregaFormPage.tsx:111` sigue reemplazando formulario y líneas al refrescar la entrega (las acciones de esa pantalla ya invalidaban la entrega antes de este cambio; no se tocó para no alterar el flujo de surtido).
- Formulario heredado `src/pages/ProductoFormPage.tsx` (no enrutado; la ruta usa `src/pages/ProductoForm`): sin cambios.

## Mantenimiento

Tras agregar consultas, RPC o triggers: `bunx tsx scripts/gen-mapa-refresco.ts` y commitear `lectores.generated.ts`.
Lo que el análisis no detecte se agrega en `LECTORES_MANUALES` / `ESCRITURAS_EDGE` de `refrescoTrasEscritura.ts`.
